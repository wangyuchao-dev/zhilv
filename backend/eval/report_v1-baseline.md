**归类**：

- **规划类问题（4 题）**：`几天够吗` `怎么安排` —— 这类问句里没有景点名，向量检索只能靠语义泛化，命中率明显低于「某个景点门票多少」这类实体问句。
- **多要素问题（3 题）**：一道题要求两个景点都出现，而 top-9 只召回了一部分。

## 三、兜底题：一个被抓，一个漏了

| ID | 问题 | 结果 |
|---|---|---|
| neg-01 | 北京故宫怎么玩 | ✓ 召回 0 条（城市过滤生效，语料里没有北京） |
| neg-02 | 大连有地铁吗，几号线到星海广场 | ✗ **召回 7 条，top1 0.851** |

**neg-02 是最值得记的一条**。「大连有地铁」这个话题语料里完全没有，但因为城市是「大连」，检索照样返回了 7 条大连景点介绍，而且分数 0.851，远高于 0.80 的阈值。

**说明现在的两道防线（城市过滤 + 阈值）只能挡住「城市不存在」，挡不住「城市存在但话题不存在」。**

后果：用户问「大连有地铁吗」，系统会拿「星海广场免费」的片段去回答，这就是典型的「一本正经胡说」。

## 四、必须说明的前提

**这一版测的是「裸检索」**：直接把用户原话丢给 `retrieve_multi`，没有经过 Agent 1 的 query 改写。

真实链路是：

```
用户问题 → Agent1 拆成 3 条检索 query → retrieve_multi
```

所以 83.6% 是**最坏情况基线**。实际跑起来，「西安两天够吗」会先被改写成「西安 景点 推荐 两天 行程」，命中率应该更高。

这反过来给了一个可量化的证明：**下一版加 Agent1 改写，再跑同一套题，差值就是改写这一步的贡献。**

## 五、下一步（按性价比）

| 优先 | 改进 | 预期影响 |
|---|---|---|
| 1 | 评测加一条「改写后」链路，对比基线 | 能量化 Agent1 价值，不用改代码 |
| 2 | 兜底题加「话题级」判断：召回后看 top1 与原问题的语义相似度，而不只看绝对分数 | 修 neg-02 这类误召回 |
| 3 | 多要素题：top-9 提到 12，或对含两个实体的 query 拆成两次检索 | 修 dl-02 / sy-04 这类「只中一半」 |
| 4 | 规划类问题：在 Agent1 里显式转成实体 query（「两天」→「两日游行程」） | 修 xa-04 / cd-02 |

## 六、这份报告怎么用

答辩被问「你怎么知道它效果好」时：

> 我自己出了 30 道题，7 个城市各 4 道加 2 道兜底。基线检索命中 83.6%，整题通过 21/28。
> 失败的 7 道里 4 道是「几天够玩」这类没有实体的规划问题，因为向量检索抓不住抽象问句。
> 另外兜底题「大连有地铁吗」召回了 7 条大连景点，分数 0.851，说明城市过滤和阈值挡不住话题级别的缺失——这是我知道还没修的问题。

**能被追问、能承认边界，比报一个漂亮的 95% 可信。**
